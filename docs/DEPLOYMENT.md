# 自行部署P兜

## 1. 准备自己的环境

需要微信开发者工具、你有开发权限的小程序AppID；云同步还需要该小程序自己的云开发环境。仓库中的 `touristappid` 和空环境ID是安全默认值，不可用来完成云同步测试。

使用微信开发者工具导入仓库根目录，将 `project.config.json` 的 `appid` 改为自己的AppID。TypeScript编译插件已配置。不要把别人的AppID、环境ID或凭据复制到自己的部署中。

本项目源码无需根目录npm安装。云函数各有package.json，需要在部署时安装依赖。当前依赖声明沿用发布源码的 `wx-server-sdk: latest`；生产部署前请在自己的环境验证所解析的SDK与Node运行时，并考虑锁定验证过的依赖版本。

## 2. 本地模式

保持 `miniprogram/config/cloud.ts` 的 `envId: ''`。可以测试新增、编辑、标签、收藏、搜索、复制和导出；未连接云端时无法跨设备同步。

## 3. 云开发

1. 在微信开发者工具创建自己的云开发环境，将环境ID填入 `miniprogram/config/cloud.ts`。
2. 部署 `cloudfunctions/cloud-setup` 和 `cloudfunctions/sync-write`，选择云端安装依赖。不能只上传小程序客户端。
3. 确认两个函数部署完成且可调用；首次创建若仍处于Creating状态，待其就绪后再部署代码，不要以CLI退出码0代替检查实际success结果。
4. 所需集合为 `prompts` 和 `tags`。cloud-setup可初始化集合，也可由环境管理员事先创建。
5. **上线前配置并验证集合权限**：客户端只应读取当前用户自己的记录；新部署应拒绝客户端直接写入，让写入经sync-write执行。云函数绕过客户端规则，因此代码同时校验微信调用上下文中的OPENID和记录所有者，不能信任客户端传入的用户标识。
6. 用两个不同微信账号验证互相不可读写，用同一账号的手机/电脑验证同步。不要为解决权限报错改成“所有用户可读写”。

请以当前微信云开发控制台的规则语法和行为为准；发布前实际验证规则。仓库不自动修改云权限，也不携带线上规则的已验收证明。

## 4. 已有旧客户端时的升级

早期客户端直接写数据库，0.2.0通过sync-write版本校验写入。两者混用有边界：

- 保留客户端写权限时，旧客户端可能绕过新版事务版本校验；不能保证跨新旧版本同时编辑时的冲突保护。
- 直接关闭客户端写权限会使旧客户端上传失败，必须先准备备份、升级提示、迁移窗口与验证方案。
- 不要在无备份、无验证时直接调整生产权限；本仓库不声称已经替所有现有部署完成迁移。

建议在独立测试环境验证后再选择切换时间。历史数据的 `_openid`、版本号及删除标记需要保留；不要通过清空集合来“修复”同步。

## 5. 验收清单

- 首页点正文复制完整内容；收藏和···不触发复制；列表滑动不误复制。
- 连续中文输入、粘贴、换行、失焦和切后台，输入不清空、不被远端覆盖。
- 手机新增后电脑能收到，电脑修改后手机能收到；离线后恢复网络继续上传。
- 同条记录两端修改、请求提交后响应丢失、删除后旧设备上线，不静默丢失新编辑内容。
- 检查冲突副本、回收站恢复、彻底删除、导出与本机备份。
- 检查云函数真实日志、耗时与失败；监控费用和读写量。前台定期全量拉取不等于零成本实时推送。
- 新建账号及同一账号已有云数据时，分别验证首次开启云同步。首次启用前先导出本地内容。

## 6. 公开仓库与自己的配置

本仓库不包含 `project.private.config.json`、用户提示词、云端导出、访问令牌、私钥或临时预览码。AppID/环境ID不是访问密钥，但这里仍去除了维护者的生产绑定，防止误连。

填写自己的配置后，提交前检查diff，避免把个人配置和数据一并提交。任何真实密钥都不应硬编码；误提交后应撤销/轮换，而不是只删除当前文件。
