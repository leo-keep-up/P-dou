# 结构与同步机制

## 客户端

原生微信小程序：TypeScript逻辑、WXML结构、WXSS样式，无独立Web服务器。数据模型只有正文和标签关联，不要求另填标题；列表标题取正文首个非空行。

- `repositories/local-repository.ts`：本机提示词、标签、设置、同步元数据与最多3份快照。
- `services/prompt-service.ts`：保存、收藏、软删除、恢复与永久删除标记。
- `services/search-service.ts`：正文/标签搜索、多标签OR、收藏优先与最近修改排序。
- `services/auto-sync-service.ts`：前台调度、防抖、网络恢复与失败退避。
- `services/sync-service.ts`：版本比较、上传/下载、编辑保护和冲突副本。
- `repositories/cloud-repository.ts`：分页读取集合，经sync-write上传。

## 编辑与同步

正文在页面草稿中维护，5秒空闲/失焦/离开时保存。保存和同步状态不通过setData回写正文。编辑状态下可以上传已保存内容，暂缓远端内容合并；退出编辑再处理，避免草稿覆盖。

本机dirty标记、baseCloudVersion与cloudVersion共同追踪待上传修改。sync-write在服务端事务内检查当前版本和所有者后写入；相同内容的重复请求可返回已有结果。发生冲突时保留远端记录，另存本机冲突副本；本机请求期间继续产生的修改不能被旧请求整体清除。

永久删除保留空正文墓碑，历史物理删除的记录也需兼容处理。云同步开启后不对未上传记录直接自动清理，避免与正在进行的上传竞争。

## 不应误解的边界

- 不是CRDT或逐字协作编辑；没有端到端加密或无限历史版本。
- 定时全量分页拉取，不是云端事件推送。多用户/大数据规模需要另行评估成本和分页一致性。
- 本地脚本是模拟测试，不证明真实云事务隔离或所有异常场景安全。
- 旧客户端直接写权限与新版事务写入混用有风险，参见部署指南。
- 用户确认已完成手机/电脑基本双向同步测试；更复杂网络和竞争场景仍需部署者按清单验证。
